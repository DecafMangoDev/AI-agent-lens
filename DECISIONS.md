# Решения и результат реализации

По просьбе пользователя выбран **Codex**, не агент из первой домашней работы. Программа написана на Go 1.26 и использует только стандартную библиотеку. Исходный текст задания не потерян: `docs/ASSIGNMENT.md`.

## Что реализовано

- `analyze --input <file|directory> [--json]`, справка, коды возврата, частичный отчёт при ошибках файлов.
- Чтение native Codex rollout JSONL с привязкой вызовов к результатам по ID.
- Собственный анализ интервалов: группировка по инструменту, суммы, nearest-rank p50/p95, объединение перекрывающихся интервалов и полные основания каждого измерения.
- `prepare`: воспроизводимый экспорт минимально необходимых полей без пользовательских текстов и результатов инструментов.
- Три реальные подготовленные сессии Codex из проекта `sys`, manifest с хешами, текстовый и JSON-отчёты, ручная сверка.
- Автоматические проверки известных интервалов, перекрытий и последовательного случая, отсутствующих результатов и дат, обратных часов, связи по ID, повреждённого JSON, дублей, orphan results, нескольких ходов, пустой сессии, удаления лишних полей, ошибок каталога, ссылок и CLI. Искусственные данные находятся только в тестовом коде и явно обозначены.
- Go-runner сравнительного эксперимента: 2 задачи × 2 варианта × 3 попытки, фиксированные исходные файлы и ответы, контроль изменений, длительности, токены, журналирование ошибок и результатов.

## Архитектура

`main.go` отвечает за параметры, файлы и представление. `internal/lens` содержит модель отчёта, parser, связывание, расчёты и экспорт. `cmd/experiment` запускает внешний Codex и оценивает результат. Анализатор не зависит от исполнителя экспериментов и никогда не запускает команды из журнала.

Native rollout выбран потому, что stdout `codex exec --json` не даёт необходимых временных меток. Не приписываем внутренним инструментам длительность внешнего JavaScript-вызова: это могло бы ошибочно отнести время нескольких операций к одной. Измеряется внешний инструментальный вызов, включая обвязку и передачу событий. Правила и ограничения описаны в README.

## Полученные результаты

| Реальная сессия | Вызовы | Объединение измеренных интервалов |
|---|---:|---:|
| Проверка библиотечных диаграмм | 21 | 2.943 с |
| BPMN технического долга | 31 | 5.611 с |
| Интеграции библиотеки | 58 | 26.189 с |

Всего 110 вызовов, все имеют парные временные метки. `exec`: 108 вызовов, сумма 34.465 с, p50 0.170 с, p95 1.656 с. `wait`: 2 вызова, сумма 0.278 с. Числа относятся к событиям инструментов, а не полной продолжительности сессий. Самый долгий вызов в сессии интеграций: 3.117 с; арифметика и исходные строки сверены вручную.

Предложенная гипотеза — объединение независимых начальных чтений уменьшит число вызовов и наблюдаемое время без потери правильности. Это проверяемое предположение, не установленная причина затрат.

## Проверка и незавершённая часть

`GOCACHE=/tmp/agentlens-go-cache go test -race ./...` и `go vet ./...` выполнены успешно. Отчёты получены запуском собранного CLI на приложенных данных. Отдельный кэш нужен из-за ограничений текущей среды на запись в обычный Go cache.

**Нельзя считать всё домашнее задание завершённым:** 12 сравнительных запусков реального агента не проведены. Локальный Codex останавливается при инициализации app-server с `Operation not permitted`; это зафиксировано в `docs/archive/experiment/PROTOCOL.md`. Результаты не симулировались, новые реальные сессии не подменены тестовыми. Runner реализован и собирается, но его взаимодействие с успешно запущенным Codex здесь не проверено.

Чтобы завершить эксперимент, нужно выполнить указанную в протоколе команду в обычной среде с рабочим Codex, сохранить результаты и применить заранее заданные критерии. До этого эффективность изменения остаётся неизвестной.

## Обновление отчёта и метрик

По замечанию пользователя технический список call_id заменён сводкой по именам инструментов на русском языке. Пояснения полей доступны в справке; в основном выводе сохранены только таблицы. Подробные основания доступны с `--details`; JSON сохраняет их всегда. Контракт расширен до `agentlens.session.v2`.

Добавлены токены и доля кэша, объём JSON результатов, повторы точного входа, максимальный параллелизм, временное окно инструментов и статические ссылки на инструменты/MCP внутри `exec`. Это отдельный слой: такие ссылки не объявляются фактически выполненными вызовами и не получают длительность внешней оболочки. Анализ строк кода не исполняет JavaScript. Правила и границы — `docs/METRICS.md`.

`prepare` теперь переносит вычисленные признаки и числовой usage, сохраняя исключение исходных аргументов и ответов. Старые приложенные экспорты не изменены: для недоступных расширенных данных возвращается null. Тесты покрывают дедупликацию usage, частично отсутствующие token counters, неизвестные значения, повторы, параллелизм, исключение строк/комментариев из ссылок, сохранение метрик при экспорте и отсутствие call_id в обычном тексте. Проверки `go test -race ./...` и `go vet ./...` пройдены.

## Компактный ASCII-отчёт

Вывод сокращён до трёх блоков: сводка сессии, Codex tools, MCP tools. Рамки используют `+`, `-`, `|`; ширина русских строк учитывается по символам, длинные ячейки переносятся. Текстовые пояснения убраны в `--help` и README. Полные ID и причины предупреждений остались в `--details`/JSON.

Добавлены итог токенов (input + output) и четыре состояния вызова: success, failure, unknown, pending. Успехи и ошибки определяются только по явным признакам результата; завершённый ход или наличие ответа не заменяет проверку статуса. Для MCP сервер вынесен в отдельную колонку. Ссылки внутри exec сохранены отдельной колонкой и не увеличивают число подтверждённых вызовов.

Обновлены примеры отчётов. Проверены группировка MCP отдельно от Codex, отсутствие поясняющих абзацев, классификация результатов и сохранение её при экспорте, отсутствие двойного учёта токенов кэша и reasoning. `go test -race ./...`, `go vet ./...` и сборка проходят.

## Совместимость запуска через main.go

Рендерер таблиц перенесён из соседнего файла пакета main в `internal/report`. Поэтому работают и `go run .`, и `go run main.go`: Go загружает рендерер как импортируемый пакет. Проверены оба способа запуска на одинаковом входе с сопоставлением вывода.

## Актуальный фокус: наблюдения об ошибках и один запрос к ИИ

Этот раздел заменяет прежний выбор «собрать дополнительные метрики». Основной вопрос: какие ошибки процессов скрыты внутри успешного exec и повторяются? В основном отчёте оставлены только размеры исследованной выборки и результаты внешних инструментов. Частоты ссылок из JavaScript больше не смешиваются с количеством вызовов; дополнительные счётчики остаются в JSON для совместимости.

Исправлен разбор native Codex: `Script completed` в первом служебном текстовом блоке подтверждает завершение оболочки. Отдельные напечатанные объекты процессов сохраняют свои exit_code. Поэтому успешный exec и неуспешная команда больше не противоречат друг другу. Число результатов процессов может быть больше числа оболочек и не объявляется числом уникальных внутренних вызовов.

Наблюдения формируются детерминированно: ошибки внутри завершённого exec; повтор полного входа с тем же неуспешным выводом; недостаток данных. Каждое содержит строки и ID, факт отделён от предложения проверки. В экспорте сохранены коды, номера блоков и хеши без исходных текстов.

Добавлен `--ai`: единственный OpenAI-compatible Chat Completions запрос с ограниченным контекстом наблюдений. Реализация на Go использует схему подключения из new_agents_hw, но не запускает того агента. Контекст/ответ пишутся в отдельный файл, мнение помечено как интерпретация. Модели не доступны инструменты, полный журнал и ключи из соседних проектов. Проверки транспорта автоматические; живой провайдер не вызывался.

Старый эксперимент объединения чтений не выдаётся за проверку новой гипотезы. Сравнительные запуски остаются незавершённой частью задания; это явно отражено в README.

## Восстановление времени/токенов и очистка структуры

В компактные таблицы возвращены сумма времени, p50/p95, полнота измерений, расход токенов (вход/выход/кэш) и время без двойного учёта перекрытий. Наблюдения сохранены. Лишний параметр ссылок убран из функции вывода: статические упоминания доступны только в подробностях.

Все сессии перенесены из data в testdata; готовые отчёты — из examples в docs/reports. Старый протокол и материалы из experiment сохранены в docs/archive/experiment, устаревший исполнитель удалён. Интеграционные проверки отделены в integration_test.go; дополнительно автоматизирована сверка всех 15 синтетических сессий с expected.json. Unit-тесты находятся рядом с пакетами Go. Личные настройки и ключи не затрагивались.

Добавлены Makefile и Staticcheck с фиксированной версией v0.8.1. make lint проверяет gofmt, go vet, Staticcheck. В текущей среде сетевое разрешение proxy.golang.org недоступно: установка и запуск Staticcheck не подтверждены. Остальные проверки выполняются локально.
